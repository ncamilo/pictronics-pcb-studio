# RES-019 — Nominal tool library and explicit job binding

Status: submitted for CI. Prior integrated job commit 96feaf7e76b023f7696b4f6f3b6d299d61edf94c passed all workflows, including 150 research tests on each OS and FlatCAM reference https://github.com/ncamilo/pictronics-pcb-studio/actions/runs/45890150153.

Pure Python immutable domain tools, unique explicit IDs, nominal diameter and cutting length, optional V-bit tip and included angle. For a V-bit nominal diameter is an upper cone bound; ideal effective width is tip + 2*depth*tan(angle/2), rejected if beyond the modeled diameter or cutting length. Versioned strict JSON, illustrative fixture only. Separate process settings require explicit positive depth magnitude, maximum stepdown, plunge feed, spindle rpm, lateral feed only for milling. No recommended defaults, no real inventory or verified machine limits. Drill and end mill at equal diameters are not interchangeable. V-bit isolation uses one depth only; changing depth requires regenerated geometry. No peck, automatic tool selection or depth schedule yet.

Adapter resolves ToolSpec before isolation, and binds one explicit selection per existing actual job stage. Effective diameter must match within 1e-9 mm (numerical tolerance only); job diagnostics and geometry retained. No execution, Z motion, G-code, GUI, hardware or main changes. Manufacturing readiness always false. Physical tool measurements, feed/speed selection, spindle/axis constraints, stock thickness, depth planning and simulation remain pending. Tests include pure domain/JSON, wrong tool type and diameter, V-depth geometry, complete synthetic job binding, and actual synthetic Gerber/Excellon import. No upstream code copied.
